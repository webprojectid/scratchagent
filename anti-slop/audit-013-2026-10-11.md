# Account, Developer Setting and landing language audit

The user selected antislop as a final check. Preserve the approved matte dark surfaces and green accent.

## Findings resolved within the requested scope

1. HIGH — Access isolation: admin controls were scattered between ordinary Settings and separate admin pages. They now share Developer Setting, with server authentication and one exact email policy. Preview, URL email parameters, alternate emails, and CLI tokens cannot grant admin access.
2. HIGH — LLM connection testing sent models while the endpoint required model. The first selected model is now sent explicitly. Stored keys are selected by provider source and matching URL; environment configuration has the same fallback behavior.
3. HIGH — Provider reordering retained keys by their new position. Saved source indices now preserve each provider's key. New providers cannot inherit another provider's key; incomplete providers fail validation instead of silently disappearing.
4. MEDIUM — R-06 / readable native copy: the landing demo used Indonesian project fixtures inside English navigation. All seven demo sessions now have reviewed English titles, descriptions, acceptance criteria and task text. Both languages show the same one-sub-feature excerpt and task references; actual saved projects remain unchanged.
5. MEDIUM — R-06: animated wallet screens contained untranslated labels and Indonesian number formatting. Labels, date caption, ranges and numbers now follow the selected language. IDR remains IDR; no currency conversion is implied.
6. MEDIUM — R-04 / interaction feedback: clipboard failure could still show success. Copy now awaits the result and offers a manual fallback on failure. Password errors use an alert and reviewed translations.
7. LOW — duplicate language controls: desktop and mobile landing switches were removed. Account Language settings remain the control for English US and Indonesian.

## Practical limits

Browser tier previews verify navigation/rendering, not real authenticated writes. Account storage, tier/quota, ownership and token policies are covered by regression tests and route inspection. No real user's password, subscription, ban, API provider configuration or account was changed during QA; no paid LLM call was made. An authenticated owner session was unavailable for an end-to-end admin mutation test.

2FA remains deferred. Automatic account deletion still depends on SUPABASE_SERVICE_ROLE_KEY. Notifications are in-app. Existing local unfinished PRD/CLI work is excluded from this release.

The isolated local build emitted a nonfatal generated-CSS optimization warning after scanning temporary build inputs; compilation and TypeScript still passed. Production deploy status is tracked in docs/ACCOUNT-DEVELOPER-TODOS.md.
