# Account dashboard, color styles, and token history

Requested scope: five selectable accent styles, recent active/revoked token groups, and a statistical dashboard with a 30-day visit calendar. The approved matte dark layout stays in place. Antislop applied after implementation, as requested.

## Findings and resolution

1. R-17, R-27: Visits cannot be inferred from existing project progress. Added authenticated visit recording, a 30-day calendar, and explicit tracking-start/empty-state copy. Preview project metrics are labeled sample data; preview visits are never fabricated.
2. R-01, R-34: Alternate accents must follow the account controls rather than introduce simultaneous decorative colors. Added Scratch Green (default), Blue, Violet, Amber, and Rose to saved display preferences. Navigation, primary controls, project icons, progress, and charts follow the selected style. Brand artwork remains recognizable; error/revoked indicators retain semantic warning colors.
3. R-27, C-2: Hiding older tokens must not prevent their revocation. Default status is Active and period is Past 3 days; Revoked and Expired have separate groups, with an All time option. Active uses creation/last-use, revoked uses revocation, expired uses expiration. No token is deleted by filtering.
4. R-25, R-32: Calendar color alone would conceal visit counts. Each of 30 date buttons exposes counts in its accessible label and selected-date summary. Visible focus and 44px targets are included. Calculated text contrast is at least 5.31:1 for calendar intensity levels and 9.22:1 for primary accent/dark text across all five styles.
5. R-03, R-35: Dense calendars and sidebars need a phone layout. Calendar reflows from 15 columns to 10 and then 5; chart columns stack. Browser check at 390px found no horizontal overflow.
6. C-2: Preview project links initially targeted nonexistent sample project IDs. They now open the preview Projects list; real projects use their actual routes. Profile editing remains available as a separate Profile submenu. Dashboard is the default profile page.
7. R-02: The new task breakdown initially lacked the English translation of Blocked. Added reviewed English copy, verified in the final browser build.

## Verification

- 105 tests pass, including timezone boundaries, owner isolation, visit deduplication, token expiry/revocation/last-use filtering, and backward-compatible color defaults.
- Focused ESLint passes. Clean scoped production build and TypeScript pass with no generated-CSS warnings. Tailwind scans src explicitly to avoid temporary build artifacts.
- Dashboard renders for Free, Pro, and admin preview accounts with 30 date controls and the same non-premium statistics.
- All five theme choices, status filtering, All time, and selected-calendar-date feedback checked in browser. Mobile width 390px checked.
- Anonymous dashboard GET and POST with a claimed owner email return 401. Browser-session account authorization, origin checking, ban checks, and rate limits are reused.
- Database reads aggregate a bounded 32-day window in 15-minute buckets, using the existing owner/date index. Visit writes deduplicate per owner/30-minute bucket across tabs. Browser visibility requests are also throttled locally. Visit records do not flood the work-activity feed.
- Preview screenshot: `artifacts/account-dashboard-preview.png`.

## Limits

No historical visit counts are backfilled. Visit frequency measures visible signed-in usage in 30-minute intervals, not task productivity or exact time spent. Production authenticated database writes were not exercised with an owner session during QA; persistence uses the existing account activity table and unique dedupe key, with no new migration. User-generated project names/content stay in their original language. Unrelated unfinished CLI/PRD work is excluded from this release.
