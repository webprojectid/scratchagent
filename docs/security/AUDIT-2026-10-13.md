Date: October 13, 2026 (Asia/Bangkok). Scope: the submitted repository findings, relevant authentication/write paths, migration tooling, reachable Git history, and live Supabase security configuration. Credential values are intentionally omitted.

See [Supabase CAPTCHA documentation](https://supabase.com/docs/guides/auth/auth-captcha). Snapshot accuracy matters because generation compares the current schema with the latest snapshot: [Drizzle generation documentation](https://orm.drizzle.team/docs/drizzle-kit-generate).

## Additional live findings fixed

- The migration files declared RLS on all 18 tables, but live inspection initially found only the six account tables protected. The other twelve tables were unprotected. Applied the existing RLS-only SQL in a transaction after confirming the backend connection bypasses RLS. Live verification now shows 18 protected tables and zero public policies; the anonymous role sees zero plans, tokens, and LLM settings rows. No plan or account data was deleted.
- Account migration 0010 had been applied through the standalone helper without a ledger record. Verified all six existing tables, columns/nullability, primary keys, named checks/foreign keys/unique constraints, indexes and RLS before recording its migration hash/timestamp. No application data or account table DDL was changed. The ledger now corresponds to the eleven journal entries.
- New parser tests reproduced four failures: consumed first chunks, plain JSON misclassified as SSE, an unprocessed final event at EOF, and NaN token totals. Fixed all four. Detection reads a clone, complete EOF events are parsed, and empty usage becomes finite zero values.
- Removed an unnecessary exit listener from the unfinished local generation code. Added direct scheduling tests covering success, failure/refund/delete, and retry usage accounting. Other unfinished business-rule work was preserved and excluded from the curated security release.

## Documentation and repository size

Removed credential references and the “bug-free core logic” claim. The five old bug descriptions were not treated as fresh release evidence; current dependency, task allocation, quota, storage and generation tests provide narrower, repeatable evidence.

- Numeric BlockList checks, all-address DNS validation and cloud metadata hostname blocking are present in the LLM test route. These protections were preserved; this audit does not claim a complete formal SSRF proof.
