# Scratch Agent security validation

Date: October 13, 2026 (Asia/Bangkok). This report replaces the earlier mixed preparation/publication notes. Credential values are omitted. The subsequent self-audit fixes are tracked in [SELF-AUDIT-2026-10-13.md](SELF-AUDIT-2026-10-13.md).

## Verified outcomes from the submitted audit

| Finding | Verified state |
| --- | --- |
| Production database credentials in helper scripts | Confirmed in old source/history. Removed embedded values; helpers use environment configuration. The exposed historical DB password was rejected by its original target, while the configured replacement connected. No password was rotated during that audit run. |
| Destructive admin cleanup endpoint | Confirmed. Retired completely: 404 in every environment, with no database/authentication/deletion imports. |
| Fallback owner UUID in task generation | Confirmed. Removed. Orphaned/shared plans are rejected, and generated tasks retain the original owner when initiated by an admin. |
| LLM key fragments and historical credentials | Confirmed. Report fragments and inspected key patterns were removed. A later scan added TokenHarbor and CLI-token prefixes, and removed remaining private .env history. The corrected main history was published in d13f7bfb96a02cd4046f7ddc11b0c7df59f56d8b. User-confirmed token revocation was not independently verified with the providers. |
| Missing Drizzle snapshots / account schema | Confirmed. Snapshots 0003–0010 were reconstructed from existing SQL; both core and account schemas are in the config. An unchanged schema produces an empty generated diff. |
| Development test endpoints and reset IDOR | Confirmed. All /api/test handlers were retired in every environment. Regression tests verify 404 without storage access. |
| Client-only Turnstile | Not confirmed for the configured Supabase flow. Sign-in/sign-up already send captchaToken to Supabase Auth. A live request with fictitious credentials and no token returned captcha_failed. Widget expiry/error clearing was added. |
| Conflicting admin definitions | Confirmed. The owner email is centralized in admin-access.ts. ADMIN_EMAILS does not add developer/admin permissions; developer endpoints require the designated owner's browser session. |

Supabase performs CAPTCHA verification for its configured Auth service: [official CAPTCHA documentation](https://supabase.com/docs/guides/auth/auth-captcha). Migration generation compares schema against the latest snapshot: [Drizzle documentation](https://orm.drizzle.team/docs/drizzle-kit-generate).

## Database and parser evidence

Earlier live inspection on October 13 verified RLS on all 18 public tables, zero public policies, and no plans/tokens/LLM-settings rows visible to the anonymous role. The missing account migration ledger entry was recorded only after matching the deployed schema, constraints, indexes and RLS to the migration. No application data was deleted.

Parser regression tests cover first-chunk preservation, plain JSON vs SSE detection, EOF events without a trailing newline, and finite token usage. These are specific tested cases, not a claim that the full parser or product is bug-free.

## Corrections to previous reporting

- The initial history rewrite was incomplete: it missed TokenHarbor and CLI-token prefixes and retained historical private environment files. The broader scanner and second rewrite corrected the inspected patterns. External clones, unreachable objects and hosting caches are outside this verification.
- The earlier 35-error lint figure covered selected files only. The published snapshot had 169 errors and 84 warnings across the repository. Current backlog and the regression baseline are disclosed in the self-audit report.
- All 21 paired tracked .agents/.claude skill files were identical in the inspected revision. They are retained for agent compatibility. Unused personal output files were removed from published history; the two creator GIFs in public remain because UI references still use them.
- The security workflow was not published by the earlier release because its Git credential lacked workflow permission. The self-audit report records the follow-up workflow status.
- Supabase anonymous client keys are public identifiers, not service-role secrets. Current production AUTH_SECRET behavior was not proven during the original audit.

The August simulation/test/summary documents are archived observations. They are not current security guarantees. No audit here claims a complete exploit review of all components or complete coverage of all production account tiers.
